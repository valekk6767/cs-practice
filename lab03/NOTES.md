# Лабораторная 03 — Git-воркшоп

## Часть 2. Сравнение версий и поиск изменений

### Выполненные команды

- git log --oneline --stat — краткая история коммитов с указанием изменённых файлов и числа строк.
- git diff HEAD~2 HEAD -- lab03/calc.py — разница между двумя коммитами: что добавилось в файл между версиями.
- git show HEAD~1 — содержимое одного коммита: автор, дата, сообщение и изменения.
- git log -S"def" --oneline -- lab03/calc.py — поиск коммитов, где появлялось или исчезало слово "def". У меня функций нет, поэтому вывод пустой.
- git blame lab03/calc.py — кто и в каком коммите добавил каждую строку файла.

### Чем отличаются git diff, git show и git log

- git diff — сравнивает два состояния (рабочую папку, индекс или коммиты) и показывает разницу.
- git show — показывает один коммит: метаданные и его изменения.
- git log — показывает историю коммитов.

### Что нашли log -S и blame

- git log -S"def" — ничего не нашёл, потому что в calc.py нет функций.
- git blame — показал, что первая часть файла добавлена коммитом "Add addition", строки вычитания — "Add subtraction", умножения — "Add multiplication".

## Часть 3. Восстановление файла

### Выполненные команды

- git status — показал, что calc.py изменён.
- git restore lab03/calc.py — вернул файл к состоянию последнего коммита.
- git restore --source=HEAD~2 lab03/calc.py — взял версию файла из коммита два назад и положил в рабочую папку.
- git diff — показал разницу между рабочей папкой и последним коммитом.
- git restore lab03/calc.py — снова вернул файл к последнему коммиту.

### Чем отличаются git restore и git restore --source=...

- git restore lab03/calc.py — возвращает файл в состояние последнего коммита (HEAD).
- git restore --source=HEAD~2 lab03/calc.py — берёт версию файла из конкретного коммита и кладёт её в рабочую папку. История при этом не меняется, только рабочая копия.

### Что произошло бы с моими правками

Если бы я не вернул файл обратно, мои удалённые строки так и остались бы удалёнными в рабочей папке, и следующий коммит зафиксировал бы это. Команда git restore перезаписывает файл, поэтому несохранённые изменения теряются. Если бы правки были нужны — их надо было сначала закоммитить или спрятать через git stash.

## Часть 4. Ошибочный коммит и его отмена

### Выполненные команды

- git log --oneline — показал, что коммит "Add division" в истории.
- git revert HEAD --no-edit — создал новый коммит, который отменяет изменения ошибочного.
- git log --oneline — показал, что ошибочный коммит остался, а над ним появился "Revert ...".

### Чем revert отличается от reset --hard

- git revert — создаёт новый коммит, который отменяет изменения указанного. История сохраняется, старый коммит остаётся на месте.
- git reset --hard — передвигает ветку назад, стирая коммиты из истории. Это опасно: если коммиты уже отправлены на GitHub, у других они останутся, а локально исчезнут — получится рассинхрон.

### Почему в опубликованной истории безопаснее revert

Revert не переписывает историю, а добавляет новый коммит. Другие разработчики могут спокойно сделать git pull и получить отмену, не ломая свои локальные копии.
